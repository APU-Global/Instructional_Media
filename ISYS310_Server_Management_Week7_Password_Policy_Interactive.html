Week 7 Interactive: Password Policy Audit Lab

Week 7 objective: Turn security audit findings into Windows Server password and account lockout settings, then test your policy against the findings.

The auditor’s findings

1Some users have kept the same password for several years.
2Some passwords are only 4 to 5 characters long.
3Users rotate between 2 or 3 passwords whenever a change is required.
4Users who forget a password can keep guessing as many times as they want.

Domain password policy belongs in the Default Domain Policy; settings placed elsewhere, or blocked from the Domain Controllers OU, don’t apply as expected.

Practice: match the finding to the fix

Choose the setting or tool that addresses each situation, then select Check my answers.

Build and test a policy

Enter your settings, then select Run the audit to see whether each finding is resolved. Microsoft’s sample fine-grained policy is shown for comparison.

The starting values match the old, unenforced policy. Change them and run the audit.
Takeaway: Each audit finding maps to a setting: maximum age, length and complexity, history with a minimum age, and a real lockout threshold. Set them in the Default Domain Policy, use fine-grained policies for groups that need stricter rules, and tell users what is changing before it takes effect.
